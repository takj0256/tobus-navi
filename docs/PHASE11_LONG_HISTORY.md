# Phase 11 長期履歴・段階移行

2026-09-18。採用方針は「累積保存＋過去の類似条件を使う基礎＋直近28日補正＋当日補正」。保存期間と予測時の選択期間を分ける。

## 実装済みの保存・移行

- `archive_phase11_history.mjs local|remote INPUT_DIR ARCHIVE_ROOT`：日次version 2の原文をgzipし、SHA-256をキーにしてローカルとR2 `history-v1/daily/日付/hash.json.gz`へ保存。元のsamples、日時、天候、イベントID（存在する場合）、source_keysを保存する。既知の未来の用途のために欠けた情報を捏造しない。
- 同じ日・同じ内容は再投入せず、訂正された日次データは別versionとして保持。ローカルindexとR2の日別latestが示す1versionだけを学習入力とする。生データの過去versionを合算しない。ハッシュ/サイズ検証後だけindexを更新。
- `backfill MAX_DATES ARCHIVE_ROOT`：まだ保存していない過去日を古い順に追加。保守ジョブは1回3日まで。既に保存済みの28日窓外データの後日訂正を自動探索する処理は未実装。訂正がある場合は対象日をremoteモードで再取り込みする。
- R2ライフサイクルの削除ルールが履歴領域と重なる場合は保存処理を停止。ルール変更や古いデータ削除は自動実行しない。ローカルデータも年齢だけでは削除しない。ローカル容量、R2全体容量・操作数の監視は引き続き必要。
- `export_phase11_legacy.mjs STATE_ROOT`：実スキーマを確認し、D1 profiles/weather_profiles/job_statusをrowidキーセットページングでJSON化。`legacy-d1-v1`に分離し、旧集計値を日次観測・累積サンプルに混ぜない。D1はSELECTのみで削除・全件更新しない。
- UTC日単位で最大5,000件を移行し、読取予約予算10,000行、1ページ500行。問い合わせ前に予約を永続化し、不確かな通信失敗を自動再試行しない。実rows_readが予約を超えたら停止する。これはこのサブPCの移行処理だけの予算であり、アカウント全体の使用量上限を保証しない。
- 行数と検証済みチャンクをmanifestに記録し、途中位置を保存。部分移行はcompleteにしない。生成時刻の変化を検出したら混在を避け停止する。元D1は移行後も自動削除しない。移行は原子的なD1スナップショットではないため、旧全件更新ジョブを再開しないことが前提。
- `.writer-lock`はファイルシステムの排他ディレクトリ。異常終了で残った場合は実プロセスを確認して人が復旧する。ロックがあるから実行中と断定しない。

## 予測モデルの検証用実装（本番未切替）

`phase11-history-model.js`は長期側（28日より古い観測）と直近側を分離。前年付近の季節±45日に十分な観測日があれば季節基礎、なければ過去全体、さらに不足すれば従来の最近の統計へ戻る。季節条件には前年相当の観測の存在と最低4日/12サンプルを要求するが、これは試験用の閾値であり校正済みではない。

長期中央値に直近中央値との比を縮小して掛ける。直近成分は既存7/28日選択を維持。基礎サンプル数と直近サンプル数を分け、未来観測を除外する。信頼度は経験的スコアであり、正解確率とは呼ばない。

現時点では曜日区分（weekday/saturday/holiday）であり、月曜と金曜の区別、ダイヤ版一致、過去の交通条件一致、季節別天候の交互作用は未実装。weatherは最近28日のまま。当日交通/天候補正の本番コードには変更を加えていない。長期基礎と天候補正の二重計上を条件別に検証するまで公開不可。

`PHASE11_HISTORY_CANDIDATE=1 node tools/aggregate_phase11_json.mjs INPUT_DIR OUTPUT_DIR`で候補を生成できる。生成物にはcandidate_onlyを付け、通常のR2公開器は拒否する。全車両の多年分を一括ロードする経路はメモリ制約のため実運用には使わない。

小規模な実データ診断は次を使う。各日を読み、指定区間だけを保持するため、全車両の多年観測を一括で保持しない。

```bash
node tools/inspect_phase11_history_candidate.mjs ARCHIVE_ROOT SEGMENT_KEY AS_OF_ISO OUTPUT_JSON
```

今後は過去のみで学習して後日の実績を検証する。現行モデルとのMAE、時間帯/天候別誤差、予測範囲の包含率、欠測率を比較し、改善確認後に候補の公開仕様・Worker参照を変更する。観測期間が長いだけで精度向上としない。

## 将来のニューラルネットワーク

`predictionExample`は予測時の入力と後日の実績をprediction_idで結ぶための入力形式。入力のobserved_atが予測時刻より未来なら拒否する。実績を後から入力特徴へ混ぜない。ダイヤ版が不明ならnullとし、同じダイヤと仮定しない。

今回は契約・検証関数のみ。実際の予測ログ収集、実績との照合、交通情報取得範囲の拡張、学習モデル・推論エンドポイントは未実装。まず従来予測の残差を学習する方式を比較し、旧方式へのフォールバックを維持する。
