# 欠損補完と到着予測：原本再生デモ v2

2026-09-30。サブPCのみで学習・検証。本番/日次公開ゲートは変更しない。

## 教師データの定義

旧daily-v2のsecondsは最後の同停留所観測からの差なので再利用しない。`build_phase11_arrival_dataset.mjs`で保存済みraw gzipを読み、停留所Aへの初回切替から次のBへの初回切替までを保持する。途中で同じ停留所を観測しても開始時刻を更新しない。最初に見つけただけの車両は左打ち切りとして除外する。

車両・便・路線・方向が一致し停留所番号が1増加するものだけを使用。逆行、飛び越し、重複timestamp、120秒超の観測/取得空白、120秒超の古い配信を除外。目的変数15〜1800秒に限定。旧データとversion/targetを分離する。明示STOPPED_ATは今回0件で、**実際の停車・ドア開閉時刻ではなく次停留所が初めて観測された時刻**が正解。`crossing_lower/upper`は停留所情報の切替を挟む観測時刻であり、実到着の保証区間ではない。

原本の実受信メタデータはローカルgzipにないため、予定分末とfeed時刻の大きい方を再生時計とする。これは厳密なオンライン配信遅延の再現ではない。リアルタイム本番精度を証明するには実受信時刻付きの予測ログと実到着ラベルが引き続き必要。

## 二つのモデル

- 補完：区間所要時間の推定。既知の区間についてのみ評価し、欠けた便・車両数・位置情報は生成しない。
- ETA：その時点から次停留所の初回観測までの残り秒数。到達済み地点や15秒未満のラベルは今回の対象外。後続停留所への累積予測は未実装。

別々のMLP（14→32→16→1、1,025パラメータ）を既存NumPy学習器で学習。seed31、最大35epoch、検証早期停止。特徴は累積中央値、直近28日中央値、当日中央値、MAD、件数、時刻/曜日周期、経過秒数、直近完了区間の秒数/鮮度、欠損分数。天候・交通・季節はまだ入力しない。今回は7日しかなく28日と累積の履歴範囲は実質同じ。

研究用基準は累積0.5＋直近28日0.3＋当日0.2の中央値混合、ETAは既に経過した秒を引く。本番PWAの機械予測ではない。基準にNN残差（±120秒上限）を加える。標準化は学習標本のみ。

## 漏洩防止と補完の扱い

- 9/23〜26を学習、9/27を検証、9/28〜29をテスト。学習期間内で頻出24区間と一意な次停留所対応を選ぶ。テストの行先を入力から推測したことにしない。
- 正解の確定時刻が分割境界を越す行を除外。履歴は予測起点より厳密に前に判明した実測だけ。検証日は前半をモデル選択、後半を残差幅/採否判定に分離し境界をまたぐラベルを除く。
- 補完試験は毎時先頭の1/10/40分を人工欠損とし、区間開始がその範囲にある例を評価。隠れた時間帯に判明した正解はすべて履歴から除く。同じ標本が異なる欠損長の試験に登場するため独立標本として合算しない。生protobufを隠して車両追跡から再構築する試験ではなく、区間レベルの条件付き補完試験である。
- 校正標本でMAEが5%以上改善しP90が悪化しない場合だけデモ内でNNを選択。それ以外は統計基準へ戻す。本番はどちらも常に無効。
- 残差90パーセンタイルによる幅は参考値で、事故・台風・未観測条件を含む確率保証ではない。
- 出力は`provenance=estimated`、モデルID、推定幅、`observed_sample_increment=0`、`training_eligible=false`、`candidate_only=true`を持つ。推定ラベルの教師への混入は拒否。`estimated-candidates.json`はテスト例の候補で、実欠損原本の復元結果ではない。
- 元raw/daily/R2/D1は読み取り/書き込みしない（元rawのみローカル読取）。生成先は新規ファイル/ディレクトリ限定で既存実験を上書きしない。

## 初回結果

入力9,566ファイル、343,749区間ラベル。stale判定1,091,578件、状態reset837,167件（車両観測単位であり欠損分数ではない）。学習は選択24区間のみ。

| 用途 | 学習/選択検証/校正/テスト件数 | 基準MAE | NN MAE | 基準P90 | NN P90 | デモ判定 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 補完 | 2275 / 213 / 213 / 591 | 14.081秒 | 14.675秒 | 28.900秒 | 32.177秒 | 基準へ戻す |
| ETA | 3899 / 42 / 42 / 197 | 13.557秒 | 10.831秒 | 32.080秒 | 25.694秒 | NN候補を選択 |

補完の個別欠損試験：1分29件でMAE16.186→14.359秒、10分372件で14.135→13.591秒、40分1460件で13.658→14.936秒。長い欠損でNNが悪化した。今回の39分の実欠損を安全に補えるという証明ではない。

ETAの±30秒以内率87.82%→92.89%。参考幅のテスト被覆率はETA80.71%、補完85.11%で、90%を保証できない。短区間・正常に追跡できるケースへ偏り、実測欠落時ほど条件が悪くなり得る。テスト結果を見て同じテストへモデルを調整していない。今後の比較では新しい保留期間が必要。

## 再現・閲覧

Python NumPy（既存環境）、Node22。サブPCで1スレッドCPU学習のみ。

```bash
mkdir -p docs/local/dual-ml-new
node tools/build_phase11_arrival_dataset.mjs RAW_GZIP_ROOT docs/local/dual-ml-new/dataset.json 2026-09-23 2026-09-29
OPENBLAS_NUM_THREADS=1 python3 tools/train_phase11_dual_demo.py docs/local/dual-ml-new/dataset.json docs/local/dual-ml-new/result --segments 24 --epochs 35
node tools/check_phase11_dual_demo.mjs docs/local/dual-ml-new/result
python3 -m http.server 8767 --bind 127.0.0.1 --directory docs/local/dual-ml-new/result
```

初回成果物：`docs/local/dual-ml-20260930/result-v2`、元ラベルは同親ディレクトリのdataset.json。いずれもGit対象外。本番コピーには移さない。ブラウザは200例の再生で、オンライン影予測サービスではない。

```bash
OPENBLAS_NUM_THREADS=1 python3 -m unittest discover -s tests -p 'test_phase11*demo.py'
npm run test:js
```

Python/JSの推論200例の最大差1.43e-14秒。ブラウザ表示/切替/次の例を確認する。次段階は受信時刻・本番予測値の影ログ、到着ラベル品質の検証、長期間/路線別評価、実際の欠損区間に対する採用判断。日次ゲート解除や推定値の本番統計混入はこのデモに含めない。
