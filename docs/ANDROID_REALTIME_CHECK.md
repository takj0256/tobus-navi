# Android実機でのリアルタイム確認

1. GitHub Pagesへ公開後、Android Chromeでアプリを開く。
2. 系統を選び、「接近中のバス」が表示されるか確認する。
3. 画面を30秒程度表示し、最終更新時刻が更新されるか確認する。
4. 画面を別アプリへ切り替えて戻り、直後に再取得されるか確認する。
5. 機内モードを一度有効にし、時刻表は残るが車両位置がオフライン表示になることを確認する。
6. 機内モードを解除し、自動的に再取得されることを確認する。

## 直接取得できない場合

UbuntuでHTTP応答とCORSヘッダーを確認できます。

```bash
python3 tools/check_realtime.py
```

Android側で「ネットワークまたはCORSエラー」と表示される場合は、`worker/` をCloudflare Workersへ公開し、`js/config.js` の `REALTIME_PROXY_ENDPOINT` にURLを設定してください。

## Phase 7追加確認

1. 複数系統が同じのりばを使用する停留所を開く。
2. 「こののりばの接近情報」をタップする。
3. 接近中のバスが系統をまたいで到着順に並ぶことを確認する。
4. 各カードに系統番号・行き先・現在位置・あと何分・何停留所前が表示されることを確認する。
5. 「停留所間の推定位置」を左右にスクロールし、乗車停留所が左端に表示されることを確認する。
6. バス記号をタップし、この先の停留所への推定到着が開くことを確認する。

## Phase 10追加確認

1. 車両カードに「停留所更新から○秒」と表示されることを確認する。
2. 初回は「先行車実績なし・時刻表基準」と表示されることを確認する。
3. 同じ画面を数分開き、車両の報告停留所が切り替わった後に先行車サンプル数が表示されることを確認する。
4. 遅い区間では「やや遅め」または「混雑傾向」と表示されることを確認する。
5. 更新が遅れてもバス記号が次の停留所を越えず、更新待ちになることを確認する。
6. アプリを再起動しても端末内に保存した区間実績が使用されることを確認する。
